# Работа с iPhone

Этот файл — как вести весь проект, не имея компьютера: чем править код, как
коммитить, как запускать сборку и смотреть, что упало, как ставить обновление
на телефон. Компилировать локально нельзя нигде на iPhone — это единственное,
что нужно делать через GitHub Actions.

## Чем редактировать код

Варианты, которые подходят для этого репозитория (текстовые файлы: `.swift`, `.yml`, `.md`):

1. **GitHub Mobile** (приложение) — удобно для мелких правок, чтения кода и PR.
2. **github.com в Safari** — встроенный редактор GitHub, подходит для большинства правок.
3. **github.dev** — тот же репозиторий, открытый как `https://github.dev/rachimanna/CasperTelegram`
   в Safari: полноценный редактор кода (VS Code в браузере), с подсветкой синтаксиса.
4. **Working Copy** — полноценный git-клиент для iOS: клонирование, ветки, коммиты,
   пуш, диффы. Удобен для более сложных правок нескольких файлов сразу.

Все три варианта работают без Mac.

## Что делать нельзя

- Компилировать iOS-приложение прямо на iPhone (запускать `xcodebuild`, открывать
  `.xcodeproj` в Xcode) — на iOS нет Xcode и компилятора Swift для iOS-таргетов.
  Компиляция — только через GitHub Actions на `macos-latest`.
- Редактировать сгенерированные файлы: `Sources/App/Secrets.generated.swift`,
  `Resources/Info.generated.plist`, `project.local.yml`, любой `.xcodeproj` —
  они не в git и перезаписываются скриптами.

## 1. Сделать коммит

1. Внесите правку через GitHub Mobile, Safari, github.dev или Working Copy.
2. Напишите короткое сообщение коммита.
3. Закоммитьте прямо в `main` (если правка небольшая) или создайте отдельную
   ветку и Pull Request — GitHub Mobile и Safari умеют оба варианта.

## 2. Запустить сборку

CI (`.github/workflows/ci.yml`) запускается **автоматически** при каждом push
в `main` и при каждом pull request — ничего вручную нажимать не нужно, если
цель — просто проверить, что код собирается и тесты проходят.

Чтобы собрать релиз для TestFlight, нужно запустить workflow вручную:

1. Откройте репозиторий в Safari или GitHub Mobile → вкладка **Actions**.
2. Выберите **Release → TestFlight** в списке workflow слева.
3. Нажмите **Run workflow**, при желании впишите текст в поле «Что нового
   в этой сборке», подтвердите.

Требует заполненных GitHub Secrets — см. [SECRETS.md](SECRETS.md). Если секретов
не хватает, workflow сразу и честно упадёт на шаге «Проверить наличие секретов»
с понятным сообщением, какого секрета не хватает.

## 3. Посмотреть, что упало

1. Actions → откройте нужный запуск (сверху список, самый свежий — первый).
2. Красный крестик у шага показывает, где именно сборка остановилась —
   разверните шаг тапом, лог откроется прямо в браузере.
3. У CI (`ci.yml`) после прогона всегда сохраняется артефакт `test-results`
   (`build/TestResults.xcresult`) — можно скачать и открыть на Mac, если он
   появится, либо ориентироваться по логу шага «Собрать и протестировать».
4. У Release (`release.yml`) в конце сохраняется артефакт `Casper-ipa`
   (`build/export/*.ipa`) — полезно для отладки экспорта, даже если выгрузка
   в TestFlight не удалась.

## 4. Поставить обновление на телефон

После успешного запуска **Release → TestFlight**:

1. Дождитесь, когда сборка появится в App Store Connect → TestFlight
   (обычно несколько минут после выгрузки, иногда чуть больше — Apple может
   обрабатывать сборку).
2. Откройте приложение **TestFlight** на iPhone.
3. Найдите Casper в списке и нажмите **Обновить** (или **Установить**,
   если это первая установка).

Подробная разовая настройка TestFlight — в [INSTALL-IPHONE.md](INSTALL-IPHONE.md).
